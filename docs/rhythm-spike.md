# 敲击节奏技术验证（v0.3 Spike）

> 目的：验证"录制一段点按节奏 → 传输 → 对方腕上按同样节奏回放"这条链路是否成立、节奏感是否可辨识。

## 数据模型

`Rhythm`（`BetweenUs/Shared/Models/Rhythm.swift`，双 target 共享）：

- 表达：点击间隔序列 `gaps: [Int]`（毫秒），长度 = 击数 − 1
- payload：`rhythm:120,300,120`（复用现有 kind 单字段通道，自包含，对方无需预存）
- 校验（防脏数据）：2–12 击、单间隔 60–1500ms、总时长 ≤10s，不合法即 `init?` 返回 nil
- 内置：心跳 `[140,320,140]`、敲门 `[180,180,180]`、浪 `[420,320,240,160,100]`

## 回放引擎

`RhythmEngine`（Watch 端）：

- **方案 A（已实现，默认）**：`Task.sleep` 时序 + `WKHapticType.click`。系统调度误差 ±20–40ms，对 ≥100ms 的间隔，节奏感预期可辨识。零资源成本。
- **方案 B（接口已留）**：`WKInterfaceDevice.play(_: Data:)` 播放预生成 haptic 文件，精度高、可表达强弱。当前实现为 fallback（行为等同 A），待用 haptic file generator 生成资源后替换。

## 验证路径

1. Watch 打开 App → 「节奏实验室（实验功能）」
2. 播放内置节奏（心跳/敲门/浪），切 A/B 方案对比体感
3. 「点我开始」后按自己节奏点按 → 回放 → 看间隔条形图是否符合预期
4. 联调：payload 区显示的 `rhythm:...` 字符串即传输值，可经 Watch→iPhone→Worker→对方 Watch 全链路回放（`IncomingTouch` 已识别 `rhythm:` 前缀并路由到引擎）

## 验证通过的标准

- 录制的节奏回放后肉眼可辨（间隔条形图形状一致）
- 心跳/敲门/浪三个内置节奏听感可区分
- 全链路（异端回放）节奏形状不失真

## 已知边界

- 方案 A 的时序精度依赖 RunLoop 空闲度，Watch 前台执行任务时误差可能增大——若验证不达标，加速推进方案 B
- 节奏与文字触感互斥（一个 payload 只能是一种），产品化时如需"节奏+文字"要扩展 payload 结构
